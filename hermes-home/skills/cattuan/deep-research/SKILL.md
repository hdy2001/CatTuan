# 深度搜索

## 步骤
0. **加载延迟工具**：deep_web_search 和 read_webpage 是延迟加载工具。第一次调用前必须先 tool_search 搜索 "deep web search" 和 "read webpage" 加载工具列表，然后 tool_describe 加载这两个工具的 schema，最后才能用 tool_call 调用。跳过 tool_describe 直接 tool_call 仍会报 "Tool does not exist"，浪费一轮。
1. **拆问题**：先想清楚要回答哪几个子问题（例如「有哪些途径」「各自要什么条件」「哪个最省事」）。
2. **多角度搜**：用 deep_web_search 搜 3–6 次，每次换角度：官方说法、经验帖/攻略、对比评测、最新消息（加年份）、反面情况。中文、英文名都可以试。
3. **读原文**：挑 4–8 个最相关、最可信的结果用 read_webpage 读正文。优先官方网站、机构页面（图书馆、出版社、政府）、信息更新时间近的页面。读不到正文就换下一个，别在一个页面上卡住。
4. **交叉核对**：关键事实（价格、条件、时间、名称）至少两个来源对得上才算确定；只有一个来源的写明「仅一处提到」。
5. **控制预算**：最多 6 次搜索、10 次读网页。信息够了就停。


## 报告格式（严格按这个写，App 会解析；报告在 App 里单独一份，用 Markdown 排版）
先单独一行写 `REPORT:`，报告从下一行开始（前面边做边说的过程话不算报告）。
1. **结论**：第一段 1–2 句，直接回答用户的问题（给出推荐 / 答案本身，不是「本报告将介绍…」）。
2. **要点**：用 `## 小标题` 分节，每节用 `- ` 列表，每条一句话，写具体的名称、数字、价格、时间、条件，后面标来源编号，例如「- 持国家图书馆读者卡可在线免费读博看期刊 [2]」。
3. **对比**：比较几个选项（地点、产品、方案、价格）时用 Markdown 表格（`| 名称 | 价格 | 交通 | 适合谁 |`），表格里也可以标 [n]。表格最多 4 列、每格不超过 15 字（用户在手机上看）；表格里已经有的信息，下面不要再按选项逐个重复，要点里只补表格放不下的关键细节（地址、要预约、坑）。
4. **注意事项**（可选）：最多 3 条，只写会影响决定的。

写作要求：信息密度高。不写客套和过渡（「综上所述」「值得一提的是」「希望对你有帮助」），不复述问题，不写「本报告」，同一件事不说两遍；没查到、不确定的写「未查到」「仅一处提到」，不要编。整份报告一般 300–800 字。
最后单独一行写 `SOURCES:`，下面每行一个来源：`[编号] 标题 | 网址`，只列真正引用过的。

## 交付物变体
- **研究报告**（默认）：按下方「报告格式」输出。
- **可视化网站**：当用户要求「做成网站 / 可视化 / 单页 HTML / 地图标注」时，把调研结果做成一个自包含的 HTML 文件（内联 CSS/JS，无外部依赖），中文界面，包含：交互式地图（标注点位）、信息卡片（名称/地址/价格/交通）、路线参考、避坑指南。参考 `references/seoul-medical-clinic-data.md` 获取首尔医美结构化数据。
  - **重要**：做网站前先 skill_view web-page 加载网页制作技能，按里面的设计要求、JS 兼容性规则和地图指南做。deep-research 负责调研内容，web-page 负责页面实现。
  - 用户中途追加「做成网页」要求时，已查到的信息不用重查，直接按 web-page 技能把已有内容做成页面。

## 中途修改与迭代
- 用户可能在搜索中途修改目标（如换城市、换筛选条件）。收到修改后，已查到的信息、读过的网页不用重查，只补做或重做需要改的部分。
- 如果已发布过网站，用同一个 `site_id` 更新，不要重新发布新网站。
- 修改后重新输出完整报告（REPORT: + SOURCES:），确保报告与最终交付物一致。
