喵团聊天接口

核心聊天功能的 HTTP + SSE 接口。根据 app/server.mjs 当前代码（main 分支，含 Bearer token 支持）整理，并于 2026-10-23 在本地逐个实测过。

概览与鉴权

项说明
Base URL本地 http://localhost:3210；线上为部署时的 PUBLIC_ORIGIN（HTTPS）
格式请求和响应都是 JSON（Content-Type: application/json）。请求体默认上限 1 MB，/api/message 是 10 MB
鉴权两种方式，查的是同一张会话表，30 天有效、一直在用就自动续期：
原生 App（Swift）用 Bearer token：登录时请求体加 "token": true，响应里拿到 token，存进 Keychain，之后每个请求（包括 SSE 和图片）带 Authorization: Bearer <token>。这种方式不下发 cookie。
网页用 Cookie：登录成功后服务端下发 HttpOnly cookie。本地 cookie 名 cattuan_sid；线上 HTTPS 时是 __Host-cattuan（带 Secure）。
收到 401 就说明 token 失效了（退出、过期、账号被停用、密码被重置），回登录页
Origin 校验非 GET 请求如果带了 Origin 头，必须等于 App 自己的源（PUBLIC_ORIGIN），否则 403 forbidden origin。原生 App 不带 Origin 的不受影响；WebView 或别的域名下的网页会被拦
错误统一是 {"error": "中文提示"}，提示文案可以直接展示给用户。常见码：400 参数不对，401 未登录，403 来源不对，404 不存在（或不属于你），409 状态不允许，413 太大，429 额度用完或登录试错太多
隔离所有接口只能访问当前登录账号自己的数据。拿别人的 id 来查一律 404
额度普通成员每天 300 条消息、40 个后台任务（环境变量可调），超了返回 429。管理员不限

Swift 接入示例

// 登录：拿 token 存 Keychain
var req = URLRequest(url: base.appending(path: "/api/auth/login"))
req.httpMethod = "POST"
req.setValue("application/json", forHTTPHeaderField: "Content-Type")
req.httpBody = try JSONSerialization.data(withJSONObject: ["name": name, "password": password, "token": true])
// 响应 { ok, name, role, token }

// 之后每个请求
req.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")

// SSE：用 URLSession 逐行读，没有第三方库也行
var sse = URLRequest(url: base.appending(path: "/api/events"))
sse.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
// 服务端每 15 秒发一次 ping，默认的 60 秒空闲超时就够用
let (bytes, resp) = try await URLSession.shared.bytes(for: sse)
guard (resp as? HTTPURLResponse)?.statusCode == 200 else { /* 401 → 回登录页 */ return }
for try await line in bytes.lines where line.hasPrefix("data:") {
    let json = Data(line.dropFirst(5).utf8)   // {"type":"message","message":{…}}，解码后按 type 分发
}
// 断开后：重连 SSE，然后重新 GET /api/state

一次聊天的完整流程

  1. POST /api/auth/login（带 "token": true）登录，拿到 token。
  2. GET /api/events 建立 SSE 长连接，整个会话期间保持开着。所有回复都从这里推回来。
  3. GET /api/state 拉初始数据：当前聊天的最近 200 条消息、聊天列表、最近 50 个任务。
  4. POST /api/message 发用户的话。服务端会等调度模型想完才返回 {"ok":true}（实测约 6 秒），响应里不带回复内容。
  5. SSE 依次推来：message（用户自己这条）→ activity（running，"想想怎么回"）→ message（喵团的回复）→ activity（done）。
  6. 如果调度模型判断要派后台任务：回复消息带 taskId，随后推 task 事件（queued → running → done/failed）。任务跑完后，喵团会再推 1–3 条带 partOf: 任务id 的消息转述结果，内容长时最后再跟一条 report 卡片。
client                          server
  │ POST /api/message {text}  ──▶ │ 存消息、调用调度模型（约 6 秒）
  │ ◀── SSE message(role=me)      │
  │ ◀── SSE activity(running)     │
  │ ◀── SSE message(role=bot, taskId?)
  │ ◀── 200 {"ok":true}           │
  │ ◀── SSE task(queued→running→done)   ← 有后台任务时
  │ ◀── SSE activity(deliver …)   │
  │ ◀── SSE message(partOf=任务id) × 1–3，最后一条可能带 report

POST/api/auth/login

// 请求（原生 App）
{ "name": "按钮测试", "password": "******", "token": true }
// 200：不下发 cookie
{ "ok": true, "name": "按钮测试", "role": "member", "token": "Hk3…（43 位）" }

// 请求（网页）：不带 token 字段
{ "name": "按钮测试", "password": "******" }
// 200（同时 Set-Cookie）
{ "ok": true, "name": "按钮测试" }
// 401 {"error":"名字或密码不对"}   429 {"error":"试错太多次了，15 分钟后再试"}

同一 IP 错 50 次或同一名字错 10 次，锁 15 分钟。

GET/api/auth/me

// 200
{ "name": "按钮测试", "role": "member" }   // role: "admin" | "member"
// 401 {"error":"请先登录"}  ← SSE 断线后用它判断是不是登录过期了

POST/api/auth/logout

// 带着 Bearer token 或 cookie 调用：200 {"ok":true}，这个会话（token）立刻作废
// 只作废当前这一个，同一账号在别的设备上的登录不受影响

注册一个成员账号并直接登录（管理员账号只能用 node scripts/user.mjs add <名字> --admin 建）。本机（PUBLIC_ORIGIN 不是 https）默认开；线上默认关、返回 404，要用时给 App 设 ALLOW_REGISTER=1。

// 请求：和登录一样，加 "token": true 拿 Bearer token，不加则 Set-Cookie

// 200 { "ok": true, "name": "按钮测试2", "role": "member", "token": "…" }

聊天接口

GET/api/state 进入 App 和 SSE 重连后调用

{
  "me": { "name": "按钮测试", "role": "member" },
  "currentChat": "c_mvhsibcr42e630",
  "messages": [Message, …],     // 只有【当前聊天】的最近 200 条，按时间正序
  "chats": [Chat, …],           // 最近更新的在前
  "tasks": [Task, …],           // 所有聊天共用，最近 50 个
  "activity": [Activity, …],    // 正在进行的事
  "goals": […]
}

POST/api/message 核心

// 请求
{
  "text": "后台帮我写一份杭州三日游行程",
  "images": ["data:image/jpeg;base64,..."],   // 可选，最多 3 张，每张 ≤ 8 MB，整个请求 ≤ 10 MB
  "ask": { "id": "m_xxx", "answers": { "q0": "两个人" } }  // 可选：用户在提问卡片上选完时带上
}
// 200 {"ok":true}             ← 回复内容不在这里，在 SSE 的 message 事件里
// 400 {"error":"empty"}        ← text 为空且没有图
// 429 {"error":"今天的额度用完啦（每天 300 条消息），明天再来～"}
消息会发到服务端记录的"当前聊天"（state.currentChat），请求里没有 chatId 参数。切换聊天要先调 POST /api/chats/:id/open。

图片会存成 /api/uploads/u_xxx.jpg，用户消息的 images 里返回这个地址，要带鉴权访问（只能看自己的）：Swift 里不能直接把地址交给图片控件，要用带 Authorization 头的请求去下载。前端发送前会先把图缩到 1280px。

GET/api/chats?q=关键词

{ "chats": [Chat, …], "currentChat": "c_xxx" }
// 带 q 时搜标题和全部消息内容，preview 换成命中的那句话

POST/api/chats 新建聊天

{ "chat": Chat }
// 如果当前聊天里用户一句话都还没说过，就直接返回当前聊天，不再新建。
// 新聊天会自动带一条欢迎消息（SSE message），并切成当前聊天（SSE chats）

POST/api/chats/:id/open 切换聊天

{ "currentChat": "c_xxx" }   // 404 {"error":"这个聊天不在了"}
// 切完后调 GET /api/state 拿这个聊天的消息

DELETE/api/chats/:id

{ "currentChat": "c_yyy" }   // 删的是当前聊天时，切到最近一个；一个都不剩会自动新建
// 只删聊天和里面的消息，后台任务还在

后台任务接口

任务一般由聊天自动派出，不需要 client 主动创建。以下是任务卡片上的操作：

POST/api/tasks/:id/steer 修改 / 插话

// 请求
{ "text": "改成两天一夜，再加一个预算估算" }
// 200：返回一条 Revision
{ "id": "r_xxx", "at": "…", "text": "…", "round": 2, "state": "round" }
// state = "round"：任务已结束，按新要求开第 N 轮（round+1，重新排队）
// state = "sent"：任务正在跑，新要求已插进当前这一轮
// 400 {"error":"改不了这个任务"}  ← text 为空，或任务不能改

POST/api/tasks/:id/stop

{ "ok": true }   // 同时推一条 bot 消息「好，「xx」先停了～」（带 stopOf）
// 409 {"error":"这个任务已经结束了"}

POST/api/tasks/:id/retry

{ "ok": true }   // 只能重试 failed / stopped 的任务；推一条「重新去办：xx～」
// 409 {"error":"这个任务没失败，不用重试"}   429 额度用完

实时事件（SSE）

GET/api/events

标准 text/event-stream，每帧是一行 data: {JSON}，没有 event: 名、也没有 id:。连上先收到 {"type":"hello"}，之后每 15 秒一个 : ping 注释行保活。只推给当前账号自己的连接；同一账号可以开多条（多设备都会收到）。未登录 401。

type负载含义 / client 怎么处理
hello—连接建立
messagemessage: Message新消息，或者已有消息被更新（比如提问卡片被回答了，会用同一个 id 再推一次）。按 id 做 upsert。消息的 chatId 不是当前打开的聊天时，只更新列表，不插进当前对话
activityactivity: Activity喵团正在做的事和当前步骤（顶栏状态 / "…"打字提示）。status 变成 done/failed 时结束
tasktask: Task任务有变化就推完整的任务对象，按 id upsert
chatscurrentChat聊天列表或当前聊天变了（新建、切换、删除）。收到后重新拉 /api/chats
goal / goal-removed…目标，不属于聊天核心，可先忽略
browser / browser-frame…任务用浏览器时的实时画面，可先忽略
断线重连：SSE 没有事件序号，服务端不会补发断线期间的事件。重连后请重新 GET /api/state 全量刷新；如果 /api/auth/me 返回 401，说明登录过期了，回到登录页。

要和 client 约定的事

下面这些是现在接口的实际行为。有几条对原生 client 不太友好，建议上线前定下来：要么 client 按现状适配，要么服务端改。

#现状影响建议
1POST /api/message 没有 chatId，发到服务端的"当前聊天"两台设备各开一个聊天时，消息可能进错聊天建议服务端加可选 chatId 参数；在那之前 client 每次发消息前确认 currentChat
2发消息的 POST 要等调度模型想完才返回（约 6 秒），也不返回消息 idclient 不能靠响应拿到回复点发送后先本地乐观显示，等 SSE 里 role=me 的那条到了再按 id 替换；POST 的超时设 ≥ 30 秒
3SSE 没有事件 id，不补发断线期间的消息会丢重连后全量 GET /api/state；以后如果需要，可以给事件加序号
4message / task 事件既是"新增"也是"更新"只做追加的话会出现重复一律按 id upsert
5已支持 Bearer token（见「概览与鉴权」）token 是登录凭证，泄露等于账号被盗存 Keychain，不要写日志；收到 401 清掉 token 回登录页
6/api/state 只给当前聊天最近 200 条，没有分页、也没有"按聊天拉历史"的接口长对话看不到更早的消息看需求决定要不要加 GET /api/chats/:id/messages?before=
7图片用 base64 dataURL 放在 JSON 里请求体大client 先缩到 1280px 左右再传，最多 3 张
8错误文案是给用户看的中文，没有错误码client 只能靠 HTTP 状态码区分按状态码处理逻辑，error 直接展示
9非 GET 请求带了 Origin 就必须等于 PUBLIC_ORIGINH5 / WebView 换了域名会 403H5 和 App 部署在同一个源，或者在服务端把 client 的源加进白名单

本地实测结果

2026-10-23，在本机 :3210 上用测试账号「按钮测试」（成员）跑，执行层用 Pi，模型是 LongCat-2.5-Preview。

场景结果
注册（调试用）：成员账号 + 直接登录（cookie / token）；重名、密码太短、名字不合规 400；请求体里的 role 被忽略；同一 IP 第 11 个 429；HTTPS 下默认 404，ALLOW_REGISTER=1 打开通过
登录成功（Set-Cookie）/ 密码错 401 / 未登录访问 401通过
Origin 不对的写请求 403通过
SSE 连接、hello、未登录 401通过
普通聊天：发消息 → SSE 推 me / activity / bot 回复（POST 约 6 秒返回）通过
空消息 400通过
聊天派后台任务 → task queued/running/done → 结果分 3 条转述 + report 卡片（任务 9 秒完成）通过
已完成任务 steer → 开第 2 轮（state=round）；运行中 steer → state=sent，新要求并进当前这一轮通过
运行中 stop → stopped + 停止消息；重复 stop 409通过
stopped 后 retry → 重新排队；运行中 retry 409；不存在的任务 404通过
带图消息：图片存成 /api/uploads/…，能带 cookie 取回（8×8 的测试图太小，识别任务按预期失败，并把失败转述回聊天）通过
聊天搜索、新建、切换、删除；删除不存在的聊天 404通过
退出登录后会话作废 401通过
Bearer token：登录 / 注册拿 token（不下发 cookie）；用 token 调 me、state、SSE、发消息、取图片；token 错 401；scheme 大小写不敏感；退出后 token 401、同账号 cookie 会话不受影响；停用账号后 token 立刻 401；"token" 不是 true 时仍走 cookie通过
