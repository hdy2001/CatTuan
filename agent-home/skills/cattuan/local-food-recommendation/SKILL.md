# 本地美食推荐搜索

## When to Use
用户说「附近有什么好吃的」「推荐餐厅」「今晚吃什么」「附近美食」「周边推荐」等，且涉及餐饮/餐厅/小吃推荐。

## 适用场景
用户想在某个区域找到评价好、适合就餐的餐厅，需要店名、人均、特色菜、距离等关键信息。

## 步骤
1. **确认区域**：任务里没写用户在哪（街道、商圈或区）时，结果里先说明需要用户补充位置，不要猜。
2. **使用工具**：调用 `web_search`，需要细节时用 `web_fetch` 读原文。
3. **搜全网**：用 web_search 搜「大众点评 + 区域 + 美食推荐」「区域 + 必吃榜 + 人均 店名」「区域 + 美食 + 推荐 + 高分餐厅 + 人均 特色菜」等组合，拿到人均、地址、特色菜等结构化信息。
4. **交叉验证**：榜单、经验帖的标题可能不含具体店名（如「望京必吃TOP10」），需要再搜区域+品类来补充具体店名和人均。至少两个来源对得上才确定关键信息。
5. **整理输出**：按「店名 · 人均 · 特色菜 · 距离」列出 3–5 个推荐，按推荐度排序。最后给一条具体建议。

## 搜索策略
- 区域关键词用街道名（如「望京」），不要用城市名（太宽）
- web_search 至少搜 3 次，角度：必吃榜/高分餐厅、具体品类（如东北菜/涮肉）、人均+店名组合
- 搜到具体店名后，用 web_search 搜「店名 + 人均 + 特色菜 + 地址」获取详细信息

## 输出格式
先 1–2 句总结（哪个最值得去、什么类型最多），然后列出 3–5 个推荐，每个包含：店名、人均、特色菜、大致位置。最后给一条具体建议（如「想吃涮肉首选鸦儿李记，性价比选维人和」）。

## 陷阱
- 搜到的经验帖可能是广告/带货，注意区分真实分享和营销内容——有具体体验描述的更可信
- web_search 搜「区域 + 美食」可能返回大量无关结果，要加「人均」「特色菜」「必吃榜」等具体关键词缩小范围
- 人均信息通常要搜大众点评/携程等平台的点评数据
- 搜索结果可能包含已关店/搬走的店，优先推荐近期（3个月内）有评价更新的店
