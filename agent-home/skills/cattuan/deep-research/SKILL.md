# 深度搜索

简单的事实问答不用深度搜索，一两次搜索就够了。要全面查清楚、调研、对比、找途径时，主 agent 派子 agent 去做（subagent 的 skills 写 ["deep-research"]，task 写清楚要回答的问题、范围和希望得到的结论）。

## 步骤
1. **拆问题**：先想清楚要回答哪几个子问题（例如「有哪些途径」「各自要什么条件」「哪个最省事」）。
2. **多角度搜**：用 deep_web_search 搜 3–6 次，每次换角度：官方说法、经验帖/攻略、对比评测、最新消息（加年份）、反面情况。中文、英文名都可以试。
3. **读原文**：挑 4–8 个最相关、最可信的结果用 read_webpage 读正文。优先官方网站、机构页面（图书馆、出版社、政府）、信息更新时间近的页面。读不到正文就换下一个，别在一个页面上卡住。
4. **交叉核对**：关键事实（价格、条件、时间、名称）至少两个来源对得上才算确定；只有一个来源的写明「仅一处提到」。
5. **控制预算**：最多 6 次搜索、10 次读网页。信息够了就停。
6. **查无结果**：小众的本地小店常常没有网络收录。搜 3 轮仍无相关结果时，不要继续换关键词硬搜——直接说没找到，并给出可操作的建议（确认名称、按地址在地图或点评 App 里搜）。不要编造。

## 报告（用 attach 的 document 附上）
document.title 写报告标题，document.body 是 Markdown 正文，document.sources 按 [1] [2]… 的顺序列真正引用过的来源（title + url）。
1. **结论**：第一段 1–2 句，直接回答用户的问题（给出推荐 / 答案本身，不是「本报告将介绍…」）。
2. **要点**：用 `## 小标题` 分节，每节用 `- ` 列表，每条一句话，写具体的名称、数字、价格、时间、条件，后面标来源编号，例如「- 持国家图书馆读者卡可在线免费读博看期刊 [2]」。
3. **对比**：比较几个选项时用 Markdown 表格，表格也可以标 [n]。表格最多 4 列、每格不超过 15 字（用户在手机上看）；表格里有的信息下面不要逐个重复。
4. **注意事项**（可选）：最多 3 条，只写会影响决定的。

写作要求：信息密度高。不写客套和过渡（「综上所述」「值得一提的是」），不复述问题，同一件事不说两遍；没查到、不确定的写「未查到」「仅一处提到」。整份报告一般 300–800 字。
附上报告后，最后的回复只写 1–2 句最关键的结论。

## 中途修改
用户中途修改目标（换城市、换条件）时，已查到的信息、读过的网页不用重查，只补做或重做需要改的部分，然后重新附上完整的报告。
